# 本地开发工作流

在 VS Code 左侧活动栏打开「本地开发工作流」，或运行「打开本地开发工作流」。

- **会话绑定**：在「设置」粘贴本机 Codex Desktop 会话 ID 或 `codex://threads/…` 链接，点击「保存会话绑定」。对话页顶部显示已绑定的标题和 ID 尾号。留空时，扩展在首次使用 Codex 时自动创建会话并保存 ID。「打开桌面会话」可直接回到同一条对话。
- **对话与派发**：输入框可讨论项目方向或直接提出实现请求。也可选择「直接提交开发任务」跳到规划。测试命令可以留空，规划会明确每个任务要补的测试，以及阶段和子任务执行的命令。展开「Codex 会话历史」可刷新桌面端已保存的最近对话。
- **测试、审查与人工验收**：需求明确时，规划完成后自动推进。存在会影响结果的取舍时才提问。Cline 同步实现功能和测试，插件验证候选提交并交给 Codex 审查。审查发现问题就返修。联合测试和审查通过后提交报告，你可以点「验收通过并归档」，或在「回应当前开发任务」中回复「验收通过」。
- **审查已有提交**：在对话中请求审查，或直接提交同样的需求，两种方式都进入同一套规划和审查。规划先确定 Git 基线、候选提交和测试。范围不清时会提问。已有代码会跳过首次实现，审查发现问题才派发返修。
- **分阶段调度**：新任务进入规划队列；通过规划后，按需要进入实现、测试和审查对应的队列。多个阶段可同时保留各自的工作树，阶段切换器决定查看和回复哪一个。单条 Codex 会话仍逐轮处理请求。暂停工作流会停止所有阶段。各阶段的待验收提交保留在各自的分支。
- **实现并行与批量审查**：实现最大并行数是项目内同时启动的 Cline 实现者上限，本地 Ollama 和云端 Act 共用。依赖未完成或写入范围冲突的任务会等待。审查会合并当时已就绪的多个提交，按提交返回结果；材料过大时分批发送。返修按文件分组，同一文件的问题交给同一个实现者。
- **执行中操作**：Codex 对话回复期间可插话或中断。选择「回应当前开发任务」可补充要求、回答工作流问题或要求调整方案。用「中断」停止开发阶段，稍后继续。暂停后在队列中可按任务回退到本轮起点，当前改动会先写入可恢复的 Git 分支。
- **队列与归档**：顶部显示当前阶段和运行任务。队列显示依赖、并发和执行槽的等待原因。验收后可在「队列 → 已验收」展开记录和最终 diff。用户自行合并或推送阶段分支。
- **单任务操作**：队列中可单独取消执行中或排队的子任务，并在原工作树重试。取消后，依赖该任务的下游任务会等待，其余任务可继续。失败或中断的对话可直接点「重试消息」。
- **审查恢复**：Codex 调用因额度或连接问题中断时，点击「继续」会复用仍通过测试且未变化的候选提交，直接恢复审查。
- **Cline 临时接管**：在设置中勾选「由 Cline Plan 接管对话和规划」，保存后应用于当前文件夹。Cline 使用其原生 Plan 配置，参考已有 Codex 讨论和本地项目进度。接管对话存在项目记录里；已有 Codex 历史读取失败时，可用本地记录继续。关闭接管后，插件将期间的对话和开发进度交回原 Codex 会话，之后恢复 Codex 对话和规划。交接失败时可点「重试交接」，接管记录会保留。审查由 Codex 负责。
- **实现模型**：勾选「实现使用 Cline Act 模型」后，当前文件夹的下一次实现或返修使用 Cline 原生 Act 供应商和模型。选云端供应商时，项目任务和相关代码会发送给该供应商。关闭时使用原有本机 Ollama，默认使用已部署的 MiMo 和本地 11434。并行档位和返修上限也在此面板设置。

会话 ID、任务、对话和归档保存在各工作区文件夹的 `.local-workflow/state.json`，Git 会忽略该目录。Codex 会话本身保存在 Codex 中。同一会话只能由一个客户端写入。如果桌面端查看后仍占用会话，需从托盘完全退出桌面端，再回扩展继续。扩展使用 Codex 完全访问权限，由提示词约定当前项目的代码改动交给 Cline。Cline 使用原生工具，插件用独立 worktree 和文件冲突检查调度任务。
